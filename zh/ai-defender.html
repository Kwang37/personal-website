01

问题不只是钓鱼邮件，更是工作中断

医护工作流程具有很高的时间敏感性。传统邮件过滤如果误删正常沟通，可能产生与放过威胁同样严重的后果。我们的产品假设是：让 AI 先识别风险并隔离可疑信息，IT 管理员再进行人工审核，能够在降低风险的同时保留必要的业务可用性。

产品目标：快速识别钓鱼、社会工程和潜在 PHI（受保护健康信息）风险，同时降低误拦截和提醒疲劳。
02

我的职责：设计 Demo 网页，并连接 AWS

我直接负责 HTML Demo 的界面设计与实现，把模型分类结果转换成医护人员和 IT 管理员能理解的页面；同时参与将前端展示与 AWS 支持的邮件处理流程连接起来。我也参与团队产品讨论和验证，但不会把全部 AWS Lambda、Agent 或安全规则的开发归功于个人。

03

为什么使用先隔离、后审核的流程

团队明确采用 quarantine-first：发现可疑内容后交给 IT 复核，而不是直接永久删除邮件。界面也区分医护员工查看收件箱与 IT 管理员审查隔离队列的权限；项目中的登录凭据仅为模拟认证，并非生产环境身份系统。

模拟邮件生成→AI 分析与 PHI 检查→分类和隔离→IT 人工复核

06

验证结果与局限

团队 README 记录了连续运行的稳定性、PHI 识别和隔离决策，并指出缓存改进提升了重复模式的处理效率。此前材料中的处理量和平均耗时应理解为合成环境下的项目测试数据，而非临床部署指标。

尚未解决的问题：置信度一致性、模拟邮件的真实性、身份认证的生产化，以及更深入的监控与审计。项目是教育与实验原型，不代表符合真实医疗机构的全面上线要求。
