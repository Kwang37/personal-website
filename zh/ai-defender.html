01

既要拦住风险邮件，也不能耽误正常工作

在医疗机构，排班调整和患者沟通都离不开邮件。一封正常邮件如果被系统误删，同样可能影响工作。我们的思路是：让 AI 先筛查风险、暂时隔离可疑邮件，再由 IT 人员决定是否放行，而不是让模型直接删除。

我们要解决的问题：识别钓鱼邮件、社交工程攻击和患者敏感信息（PHI）泄露风险，同时尽量减少误拦截和无效告警。
02

我负责的部分：演示页面和 AWS 对接

我负责设计并开发 HTML 演示页面，把邮件风险类别、处理状态和人工审核操作整理成直观的界面，并对接 AWS 后端服务。我也参与产品讨论和测试；AI 模型、Lambda 和安全规则属于团队共同完成的工作。

01 / INTERFACE

看得懂的风险提示

页面同时展示邮件内容、风险分类、处理状态和审核入口，让 IT 人员有依据地判断，而不是只看到一个分数。

02 / INTEGRATION

对接 AWS 服务

把后端返回的风险判断和操作状态呈现在页面上，让演示者能够走通从邮件筛查到人工审核的流程。

03

为什么选择先隔离，再人工复核

团队采用“先隔离、后人工复核”的方式：可疑邮件先进入隔离队列，IT 人员审核后再决定如何处理。医护员工主要查看收件箱，IT 管理员负责隔离队列和日志。项目中的登录功能只是模拟，不是可用于真实医疗机构的认证系统。

生成模拟邮件→AI 分析及敏感信息检查→风险分类与隔离→IT 人员复核

06

测试结果与待改进的问题

团队在 README 中记录了系统连续运行、敏感信息识别和邮件隔离的测试情况。处理量和平均耗时等指标来自模拟环境，不代表真实医疗机构的运行表现。

后续需要完善：模型判断的一致性、测试邮件的真实性、正式身份认证，以及更完善的日志与审计能力。这个项目仍是课程原型，尚未经过真实医疗场景所需的完整验证。
