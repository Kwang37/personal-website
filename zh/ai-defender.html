问题不只是钓鱼邮件，也是业务中断。

医疗工作者需要防范邮件欺诈和潜在的患者信息泄露，但如果 AI 误拦截正常工作邮件，同样可能干扰诊疗和运营。

团队使用虚构的牙科诊所作为实验环境，模拟不同岗位收发邮件的场景。我在简历中记录了四人团队的产品主导工作，以及与临床和 IT 相关人员开展的八次访谈；公开 README 仅能独立核对部分访谈记录，因此这里区分简历自报和仓库证据。

产品问题：如何自动化邮件风险初筛，同时为人类保留最终决定权？

项目 README 与研究链接

把安全设为工作流程，而不是一个开关。

先隔离，再审核

对可疑邮件采用 quarantine-first 策略，而不是根据模型预测直接删除。即使判断存在误差，仍有恢复与人工干预的空间。

按角色分离操作

医护角色负责收件箱查看与上报；IT 管理员查看隔离队列、审查决策与日志。演示中的身份验证为模拟机制。

让证据可见

界面不仅展示分类结果，也支持风险解释、置信度、审核状态与运行记录，以帮助技术人员理解系统行为。

使用合成数据

实验使用虚构邮件与患者资料，避免把真实受保护的健康信息引入课堂测试流程。

能够运行的原型，不等于合规的医疗产品。

系统实现了可审查的处理路径，但真实医疗场景部署还需要更严谨的性能验证、访问控制、运维与合规评估。README 坦诚记录了置信度波动、缓存尚在演进及模拟邮件真实性不足等局限。

已经证明的方向

采用隔离而非直接删除；不同岗位有不同审查界面；CloudWatch 可以提供运行证据；实验数据没有使用真实患者信息。

下一步会怎么改

校准置信度、正式衡量误报和漏报、提高授权机制强度，并在真实环境前增加专业安全审查与更接近生产的数据测试。
